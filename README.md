# Компьютерная графика

Учебный проект по курсу «Компьютерная графика», основанный на [Vulkan Starter App](https://github.com/vladeemerr/vulkan-starter-app). Лабораторные развиваются последовательно в одном репозитории.

Текущая реализация — лабораторная работа №3 «Текстурирование»: два правильных октаэдра и плиточный пол, текстурные материалы, освещение Блинн–Фонга и анимированное свечение золотых прожилок. Сохранены камера, преобразования и источники света из предыдущих работ; управление доступно через Dear ImGui.

Номер по списку — 26. При 12 вариантах формула `((26 - 1) % 12) + 1` даёт вариант **2 — правильный октаэдр**.

## Возможности

- Перспективная и ортографическая проекции с настройкой поля зрения или размера области видимости.
- Изменение оси и скорости вращения, масштаба и центра траектории выбранного объекта.
- Пространственная траектория с настройкой радиуса, высоты и скорости; независимая пауза для каждого объекта.
- Независимые положение и поворот камеры; управление мышью и WASD при удержании правой кнопки мыши.
- Процедурные нормали плоских граней и освещение Блинн–Фонга во фрагментном шейдере.
- Настройка альбедо, цвета блика и параметра блеска материала каждого объекта.
- Направленный источник и фоновое освещение; создание, удаление и редактирование точечных и прожекторных источников.
- Затухание по закону обратных квадратов и мягкие края прожектора между внутренним и внешним углами.
- Общий динамический UBO моделей с выравниванием записей по лимитам GPU; отдельный набор дескрипторов для каждого материала и служебный набор маркеров. UBO и SSBO увеличиваются по мере необходимости.
- Выбор материалов Obsidian gold, Light stone и Checkerboard независимо для октаэдров и пола. По умолчанию пол размером 64×64 покрыт чёрно-белой плиткой с квадратами размером 1×1 для демонстрации фильтрации. Карты albedo, specular и emissive; общая чёрная текстура 1×1 заменяет отсутствующие дополнительные карты.
- Анимация свечения с несколькими выборками emissive-карты по разным UV и модуляцией цвета; время и переключатель передаются через push constants.
- Загрузка текстур и статической геометрии через staging в device-local память; ожидание завершения загрузки через fence.
- Генерация mipmaps на GPU, трилинейная фильтрация и анизотропия до 16× в пределах возможностей устройства.
- Независимое скрытие визуализации точечных и прожекторных источников: цветные сферы и белые линии конусов, не зависящие от освещения.
- Выбор центра траектории, масштабирование интерфейса и сброс параметров сцены.

## Сборка в Windows

### Требования

- Git и CMake 3.20 или новее.
- Visual Studio 2022 либо Build Tools 2022 с компонентами разработки на C++ и Windows SDK.
- Vulkan SDK с компилятором шейдеров `glslc`, доступным в `PATH`.
- Видеокарта и установленный драйвер с поддержкой Vulkan 1.1 или новее.

Используется C++20. GLFW, vk-bootstrap, Vulkan Memory Allocator, Dear ImGui, GLM и stb загружаются через CMake `FetchContent`. При первой конфигурации нужен доступ к их репозиториям; вручную устанавливать эти библиотеки и инициализировать сабмодули не требуется.

### Debug

Команды для PowerShell:

```powershell
git clone https://github.com/GoJIub/CG.git
cd CG
cmake --preset msvc-debug
cmake --build build-debug --config Debug --parallel 1 -- /nr:false
.\build-debug\Debug\CG.exe
```

Запускайте приложение **из корня репозитория**: шейдеры загружаются по относительным путям из `shaders/`, изображения — из `textures/`. Форматы текстур должны поддерживать линейный blit; анизотропия включается при поддержке устройства, иначе сохраняется трилинейная фильтрация.

### Release

```powershell
cmake --preset msvc-release
cmake --build build-release --config Release --parallel 1 -- /nr:false
.\build-release\Release\CG.exe
```

Есть также пресеты `debug` и `release` для Ninja. Они требуют доступных компилятора и Ninja. Не используйте Ninja и Visual Studio в одной папке сборки. Для другого генератора задайте отдельный каталог:

```powershell
cmake --preset debug -B build-ninja-debug
cmake --build build-ninja-debug --parallel
.\build-ninja-debug\CG.exe
```

Для MSVC с Ninja эти команды выполняются в Developer PowerShell / Developer Command Prompt, где настроено окружение компилятора.

### Шейдеры

Если при конфигурации CMake найден `glslc`, шейдеры автоматически компилируются в SPIR-V при сборке приложения. Файлы `.spv` не хранятся в Git. Для ручной компиляции:

```powershell
glslc shaders/mesh.vert -o shaders/mesh.vert.spv
glslc shaders/mesh.frag -o shaders/mesh.frag.spv
glslc shaders/light_marker.vert -o shaders/light_marker.vert.spv
glslc shaders/light_marker.frag -o shaders/light_marker.frag.spv
```

После добавления новых `.cpp` включите их в список исходников в `CMakeLists.txt` и повторите конфигурацию.

## Управление

Все элементы находятся в окне `Scene controls`. Проекция и режим центра траектории общие для сцены; параметры объекта относятся к номеру, выбранному в `Object`.

Для свободного управления камерой нажмите и удерживайте **ПКМ вне интерфейса**: мышь меняет направление взгляда, `W`/`S` перемещают камеру вперёд/назад, `A`/`D` — влево/вправо относительно её ориентации. Камера летит в направлении взгляда, в том числе вверх или вниз. Отпускание ПКМ, `Esc` или потеря фокуса окна освобождают курсор. Нажатие ПКМ над интерфейсом не включает управление камерой.

| Элемент | Действие |
| --- | --- |
| `Orbit around world origin` | Включён — движение вокруг `(0, 0, 0)`; выключен — вокруг индивидуального центра |
| `Camera position`, `Pitch`, `Yaw`, `Roll` | Положение и углы поворота камеры |
| `Perspective projection` | Выбор перспективной или ортографической проекции |
| `Field of view` / `Orthographic half height` | Параметр выбранной проекции |
| `Object` | Выбор объекта 1 или 2 |
| `Material` | Материал выбранного объекта; отдельный выбор есть в разделе `Floor` |
| `Emissive color`, `Emissive intensity` | Оттенок и интенсивность свечения выбранного объекта |
| `Animate texture` | Анимация свечения; для Light stone эффект отсутствует из-за чёрной emissive-карты |
| `Rotation speed`, `Rotation axis` | Скорость в градусах в секунду и направление оси вращения |
| `Own orbit center position` | Индивидуальный центр; доступен при отключённом общем центре |
| `Scale` | Масштаб по трём осям |
| `Albedo`, `Specular color`, `Shininess` | Цвет диффузного отражения, цвет и концентрация блика |
| `Lighting` | Направление, цвет и интенсивность направленного света, цвет фонового освещения |
| `Point lights` | Добавление и удаление источников; положение, цвет и интенсивность |
| `Spot lights` | Добавление и удаление прожекторов; положение, направление, цвет, интенсивность и внутренний/внешний полууглы |
| `Show visualization` | Показ/скрытие маркеров отдельно для точечных источников и прожекторов; освещение не выключается |
| `Cone display length` | Длина изображения конуса, не ограничивающая дальность освещения |
| `Trajectory radius`, `Trajectory height`, `Trajectory speed` | Форма траектории и скорость изменения фазы в радианах в секунду |
| `Pause animation` / `Resume animation` | Остановка / продолжение движения и вращения выбранного объекта |
| `Reset scene` | Сброс объектов, камеры, источников света и параметров визуализации |
| `Interface scale` | Масштаб интерфейса от 1 до 2.5; начальное значение 1.5 |

Пауза останавливает движение объекта, но не анимацию текстуры и не редактирование параметров: изменение радиуса, высоты или масштаба сразу меняет изображение даже на паузе. `Reset scene` не сбрасывает масштаб интерфейса.

По умолчанию объекты движутся вокруг общего центра с разностью фаз π. Они находятся на противоположных сторонах в плоскости XZ, но имеют одинаковую высоту. Параметры и пауза независимы, поэтому изменение одного объекта может нарушить эту симметрию.

| `source/scene/materials.hpp` | Каталог материалов, названия и пути к картам |
| `source/graphics/gpu_buffer.*` | Создание буферов, запись CPU-данных и команды копирования геометрии |

| `source/graphics/image_loader.*` | Декодирование изображений в RGBA8 через stb_image |
| `source/graphics/materials_gpu.*` | Загрузка и очистка карт материалов, резервная текстура, выделение и обновление наборов материалов |
| `source/graphics/pipeline_utils.*` | Загрузка SPIR-V и создание graphics pipeline |
| `source/graphics/light_gizmos.*` | Создание, отрисовка и освобождение ресурсов визуализации источников |
| `source/graphics/scene_renderer.*` | Ресурсы объектов и сцены, UBO/SSBO, дескрипторы и организация отрисовки |
| `shaders/mesh.vert` | Мировая позиция, преобразование нормали и расчёт clip-space позиции |
| `shaders/mesh.frag` | Освещение Блинн–Фонга с направленным, точечными и прожекторными источниками |
| `shaders/light_marker.vert`, `shaders/light_marker.frag` | Сферы и линии конусов с постоянным заданным цветом |

У октаэдра 6 геометрических вершин и 8 треугольных граней. Для плоских нормалей используются 24 записи вершин и 24 индекса: у каждой грани собственные записи с одинаковой нормалью. Нормаль вычисляется векторным произведением рёбер. Октаэдры используют общие vertex/index buffers. Пол имеет отдельную геометрию и тот же pipeline. Модельные данные октаэдров, пола, сфер и конусов размещены в одном динамическом UBO; порядок записей: октаэдры, пол, сферы, конусы. Индексы начала групп и общее количество записей вычисляются одной функцией раскладки, используемой при записи UBO и отрисовке. Буферы октаэдра и пола хранятся в одинаковой структуре и освобождаются общей функцией.

Набор `set = 0` содержит UBO сцены (`binding = 0`), SSBO точечных источников (`binding = 1`) и SSBO прожекторов (`binding = 2`). UBO сцены хранит view-projection, позицию камеры, направленный и фоновый свет, количество активных источников. Набор материала `set = 1` содержит динамический UBO (`binding = 0`) и карты albedo/specular/emissive (`binding = 1/2/3`). Нужная запись модели выбирается динамическим смещением при привязке набора; объекты с одинаковым материалом используют один набор. Служебный набор маркеров содержит только динамический UBO. Для UBO используется `std140`, для SSBO — `std430`. Размер записи проверяется по `maxUniformBufferRange`; ёмкость общего UBO ограничена представимостью динамических смещений в `uint32_t`, размером буфера и CPU-массива. Увеличение ёмкости не превышает вычисленный предел.

SSBO хранят массивы переменной длины; при нехватке ёмкости создаётся более крупный буфер и обновляется его дескриптор. Количество источников не зашито в шейдер, но ограничено памятью и лимитами устройства. Сферы и конусы используют отдельные pipeline, матрица модели и цвет читаются из общего динамического UBO. Скрытие визуализации не изменяет данные освещения.

Матрица модели имеет порядок `T * R * S`: сначала к локальной вершине применяется масштаб, затем вращение и перенос. Вершинный шейдер вычисляет `projection * view * model * position`. Для GLM включён диапазон глубины Vulkan `[0, 1]`, направление экранной оси Y корректируется в матрице проекции.

Матрица вида — обратная матрица положения и поворота камеры. Освещение рассчитывается в мировом пространстве; нормали преобразуются через `transpose(inverse(mat3(model)))`. Ambient добавляется один раз, затем суммируются вклады источников. Тени от перекрытия источника другими объектами не рассчитываются.

Текстуры в `textures/` подготовлены для этой работы: albedo каменных материалов сгенерированы с помощью ИИ, чёрно-белая плитка построена программно, specular и emissive обсидиана получены программно из согласованной маски прожилок.

## Частые проблемы

- **CMake сообщает о несовпадении генераторов.** Выбраны Ninja и Visual Studio для одной папки сборки. Используйте прежний пресет либо отдельный каталог через `-B`.
- **CMake жалуется после переноса репозитория.** Пересоздайте каталог сборки: кэши содержат абсолютные пути. Сначала выполните конфигурацию через `cmake --preset msvc-debug`, затем сборку.
- **Приложение закрывается или не находит шейдеры.** Проверьте рабочую директорию и наличие всех четырёх `.spv`. Если `glslc` появился в `PATH` после конфигурации, повторите конфигурацию CMake или соберите шейдеры вручную.
- **Vulkan-типы подсвечены красным, но сборка проходит.** Убедитесь, что CMake успешно сконфигурирован и расширение C/C++ использует конфигурацию CMake Tools, а не только ручные include paths.
- **Не удаётся создать Vulkan-устройство.** Проверьте поддержку Vulkan и установленный драйвер видеокарты.

## Лабораторные и история

Работа продолжается в ветке `main`. Завершённые версии отмечаются тегами: `lab1` — первая лабораторная, `lab2` — вторая, `lab3` — третья. Следующие лабораторные развивают ту же реализацию; уже опубликованные теги остаются контрольными точками.

Каталоги сборки, скомпилированные шейдеры и `imgui.ini` исключены из Git. Локальные отчёты и вспомогательные файлы можно хранить в уже игнорируемом каталоге `tmp/`.
